# 检查清单

七大类。每项写清「查什么」+「**怎么验**」——第二栏才是关键，只写"查什么"的清单没有执行力。

---

## A. 机械层（可脚本化）

| 查什么 | 怎么验 |
|---|---|
| 重复词（`the the` / `of of`） | `scan.py` §重复词。注意排除导言区的 `\newtheorem{theorem}{Theorem}`——剥离命令后会变成 "theorem Theorem" 的假阳性 |
| 多余空格 | `scan.py` §多余空格。参考文献里的会议名常有多余空格，属出版社产出，不动 |
| 不可数名词误加复数 | `scan.py` §不可数名词。重点词：noise / evidence / information / equipment / research / accuracy / precision |
| 破折号用量 | `scan.py` §破折号。**改之前先数一遍**，见 SKILL.md 铁律 2 |
| 术语变体冲突 | `scan.py` §术语变体。**全文范围**比对，不是逐行 |
| 直引号不成对 | `scan.py` §直引号 |
| 括号/环境配对 | `xref.py` + P6 的结构不变性检查 |

---

## B. 语言层（必须人读）

单遍通读的召回率很低（实测约 10%）。用 P2 的多路并行 + P3 的逐条回查。

| 查什么 | 怎么验 |
|---|---|
| **拼写（"非词"错误）** | `spell.py`（`pyspellchecker`）。抓 `recieve` / `teh` / 字母转置这一类。**它抓不到"用词错误"**（`form`↔`from`、`discrete`↔`discreet`），那些仍需逐句读。命中项必须逐条回读——宏包选项、`tabular` 列格式、出版社标识符、以及你所在领域的术语与专有名词都会命中 |
| 冠词（a / an / the）缺失或多余 | 逐句读。**补冠词时同步量字符数**——见 F 类 |
| 介词搭配 | 逐句读。重点：in/on/at/of/for/to/by/with |
| 时态一致 | 注意段内混用（如全段现在时里夹一句过去时） |
| 主谓一致 | 尤其主语后跟长插入语时 |
| 单复数 | 尤其不可数名词、集体名词（data 的单复数用法要**全文统一**） |
| 悬垂修饰 | `While/After/Inspired by..., <主句>` —— 分词短语的逻辑主语必须等于主句主语 |
| 平行结构 | 列举项形式不齐（如 3 条完整句 + 1 条无谓语片段） |
| 中式英语 | 重度名词化（`provides a reflection of`）、`it can be considered that`、`exhibits poor characteristics`、`constitutes a key starting point` |
| 词形混淆 | alternate/alternating、affect/effect、principle/principal、complement/compliment、discrete/discreet |
| 句子碎片 | 无主句、无谓语 |
| **改完回读整句** | 只改动词不改主语 = 改一半，比不改更糟 |

## C. 术语与写法一致性

| 查什么 | 怎么验 |
|---|---|
| 同一术语的连字符写法 | `scan.py` 给出计数。**方向看哪个更规范**，不是哪个多 |
| 缩写大小写 | 首字母缩写展开成全称时的大小写风格，全文是否一致（`Maximum A Posteriori` vs `maximum a posteriori`），以及各领域缩写的全称写法 |
| 变量与符号名 | 正文的符号要和公式里的一致（同一参数在正文与公式里的字形、上下标） |
| 同一概念多种叫法 | 同一个量被起了好几个名字（如同一符号先后被称作 `dropout rates` / `sampling ratios` / `loss percentages`） |
| 单位与数字格式 | `20~min` vs `20 min`（不换行空格）、数值-单位间距、数组写法（`[3, 3, 5]~m`） |
| 表头措辞 | 同构的几张表，表头应完全一致（如 `Processing methods` vs `Processing Methods`） |

**判据**：作定语时带连字符通常更规范（`scale-factor error`）。但若全文多数处不带、少数处带，为了统一而去掉带连字符的那几处是"向下对齐"，**应保留并考虑统一到带连字符**，或直接不动。

## D. 数值一致性

| 查什么 | 怎么验 |
|---|---|
| 摘要的数 vs 正文的数 vs 表格的数 | `consistency.py --find <值>` 把三处摆到一起 |
| 百分比能否复算出来 | `consistency.py --improve <基线> <新值>` |
| 跨表同一量是否自洽 | 同一 RMSE 出现在多张表里时，逐张比 |
| 迭代/循环次数降幅 | 复算：`(10-8)/10=20%`、`(15-5)/15=66.7%` |
| 结论与数据是否相符 | **这条脚本查不了**。要人读：正文说"某方法整体最优"，但表里另一方法在某列更接近参考值——只有人能发现 |
| 参数设定与公式是否自洽 | 文中声称"某参数取 X 时结果衰减到 Y"，把 X 代进公式手算一遍，看是否真能得到 Y |
| 四舍五入造成的微小差异 | 0.01 级别的差异通常来自不同批次实验，报给作者确认，不要自行"修正" |

## E. 交叉引用

| 查什么 | 怎么验 |
|---|---|
| 悬空引用（引用了不存在的标签） | `xref.py`。这类**必须修** |
| 重复标签 | `xref.py` |
| 定义了但从未引用 | `xref.py`。多为公式标签，先确认再判为问题 |
| **引用指得对不对** | 脚本查不了。要人读，或渲染 PDF 看实际编号 |
| 引用措辞 vs 宏行为 | **见 SKILL.md 铁律 1**。`\eqref` 可能自带 "Eq." |
| 图表编号与正文叙述是否呼应 | 渲染对应页看 |

## F. 期刊格式合规

| 查什么 | 怎么验 |
|---|---|
| Highlights 条数与每条字符数 | `compliance.py`。Elsevier：3–5 条，**每条 ≤ 85 字符含空格** |
| 摘要词数 | `compliance.py`。默认上限 250 词 |
| 关键词个数 | `compliance.py`。默认上限 6 个 |
| 标题长度 | `compliance.py` |
| 表格跨页表头 | 检查 `\endthead` 后是否有 `\rowhead`。**注意**：在有些模板下缺 `\rowhead` 渲染结果**完全相同**（表头仍加粗、规则线正常），此时只报"写法不一致"、不要建议改——没有可执行判据的项不该进 A 类 |

**这一类最容易在语言修正时被打破**：补两个冠词就可能让一条 highlight 越过 85 字符上限。任何涉及 highlight / 标题 / 摘要的修改，**改完立刻重跑 `compliance.py`**。

## G. LaTeX 标记异常（仅提示）

这一节的问题**多半不是作者的笔误**，可能来自网页端复制、出版社排版系统、或模板本身。报告时单独成节并注明，**不要给修改建议**。

| 查什么 | 说明 |
|---|---|
| `\ubrk` | 出版社的断行点标记，前后有空格是正常的 |
| `\?{...}` | 出版社的"请核对此项"标记 |
| `\rvtissn*` / `\rvtfb*` / `\rvtiop*` | 期刊名宏 |
| `{...}` 段落分组 | 出版社的修订标记 |
| 标签名里的拼写错误 | 如 `\xlabel{Fig_Comparision_Plot}`。不渲染任何文字，改了有断链风险 → **建议不动** |
| 孤立的空宏 | 如单独一行的 `\text{}`，可能是编辑残留 |
| 表格里的占位符 | 如 `\_` 会渲染成**基线以下的孤立下划线**。要确认渲染效果再决定，用 `render.py --crop` 放大看 |

**验证渲染效果**：`render.py proof.pdf --page N --dpi 400 --crop x,y,w,h`
